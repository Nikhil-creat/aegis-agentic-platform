Advanced & Futuristic Additions

Beyond the core spec — capabilities that push this toward a genuinely autonomous, self-improving system.

agents

Reflexion memory

Failed self-correction attempts are logged with their root cause and retrieved on future runs, so the agent avoids repeating known-bad plans.

rag

Adaptive retrieval depth

Query complexity (estimated via token entropy + sub-question count) dynamically scales top-k and hop count instead of using a fixed budget.

vision

Diagram-to-graph parsing

CNN classification output feeds a downstream layout parser that reconstructs architecture diagrams into an editable node-edge graph.

execution

Speculative pre-warming

Common language images (Python, Node) are kept as warm, paused containers to cut cold-start latency below 300ms.

security

Per-tenant rate limiting

Token-bucket limits scoped to JWT subject, enforced at the gateway before requests reach agent or sandbox services.

observability

Cost-per-task tracing

Every LangGraph node span carries token usage as an OTel attribute, rolled up into a per-session dollar cost in Grafana.

Technical Deep Dive

Mock-interview-style questions on this architecture, ordered by difficulty. Built for portfolio walkthroughs and interview prep.

Why use LangGraph instead of a single long prompt with tool-calling?›
easyagents

A single-prompt loop re-sends the entire conversation history on every tool call, which is expensive and loses explicit control over state. LangGraph models the workflow as an explicit state machine (AgentState), so each node — planner, tool_router, executor, reflector — only touches the state it needs, transitions are inspectable, and retries or branches (like the self-correction loop) can be encoded as graph edges instead of prompt hacks.

What happens if a code execution container tries to access the network?›
easysecurity

It fails immediately. Every sandbox container is created with network_disabled=True, so it has no network namespace attached at all — there's no egress to block because there's no interface to use. This is enforced at container-creation time in sandbox_manager.py, not by a firewall rule that could be misconfigured.

How does the self-correction loop avoid infinite retries?›
mediumagents

The reflector_node checks state["error_count"] against MAX_SELF_CORRECTION_ATTEMPTS (3). Each failed tool execution increments the counter in executor_node. Once the ceiling is hit, the reflector short-circuits by setting final_answer directly, which every downstream node checks first and passes through unchanged — guaranteeing termination regardless of how many corrected steps get inserted into the plan.

Why cache in Redis by embedding similarity instead of exact query string?›
mediumrag

Users rarely phrase the same question identically. "How do I reset my password?" and "steps to change my password" are semantically identical but would miss an exact-match cache entirely. The semantic cache embeds the incoming query, scans cached query embeddings, and serves a hit above a cosine-similarity threshold (0.92 by default) — trading a bit of scan cost for a much higher effective hit rate, which is what actually reduces LLM spend.

Why does the vision CNN freeze the ResNet18 backbone?›
mediumvision

The backbone is pretrained on ImageNet and already encodes strong general-purpose visual features (edges, shapes, textures). Freezing it means only the small embed and classifier heads (512→128→5 params) need training on a much smaller labeled dataset of UI/diagram screenshots, which avoids overfitting and keeps training cheap enough to iterate on a laptop GPU.

The reranker adds latency. How would you keep p99 response time acceptable under load?›
hardrag

Three levers, in order of impact: (1) shrink the candidate pool before reranking — dedupe across expanded queries first (already done via candidate_pool.setdefault) so the cross-encoder never scores redundant documents; (2) batch the reranker's predict() calls and run it on GPU rather than CPU inference, which is the current default; (3) treat semantic-cache misses as the expensive path only — since cache hits already skip reranking entirely, raising the cache hit rate (via a lower similarity threshold, tuned against a false-positive budget) reduces how often the expensive path runs at all.

A container escape vulnerability is disclosed in the Docker runtime tomorrow. What's your blast radius, and how do you reduce it architecturally?›
hardsecurity

Blast radius today: the worker container has /var/run/docker.sock mounted to spawn sandbox containers, so a compromised sandbox that escapes could potentially reach the host's Docker daemon and, from there, every other container on the host. Architectural mitigation: replace Docker-in-Docker sandbox spawning with a dedicated, network-isolated "runner" VM or a gVisor/Kata Containers runtime (stronger kernel isolation than default runc), and stop mounting the host socket directly — instead have the worker call a narrow, purpose-built sandbox API service that itself holds the only Docker socket access, so a sandbox escape can't reach the orchestration layer at all.

How would you extend the agent graph to support human-in-the-loop approval before executing code?›
hardagents

Insert an approval_gate node between tool_router and executor that, when the routed tool is execute_code, sets final_answer to a pending-approval marker and persists the full AgentState (LangGraph state is serializable) to Postgres keyed by session ID instead of continuing the graph. The gateway exposes an /approve/{session_id} endpoint that rehydrates that exact state and resumes agent_graph.ainvoke from the same node — this works because the graph is a pure function of state, so pausing and resuming mid-graph requires no special-casing beyond persisting and reloading the AgentState dict.
